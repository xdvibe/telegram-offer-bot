# Размещение на Bothost

Точка входа: `main.py`. Python 3.12. Команда: `python main.py`.
Бот использует polling; публичный сайт, домен и открытый HTTP-порт ему не нужны.
Запускайте один экземпляр, без второго локального процесса с тем же токеном.

## Что загружать

Для репозитория или загрузки кода используйте только содержимое
`D:\BothostBot\bot-source.zip`. В архиве нет токена, пользователей, базы или старых копий.
Код также находится непосредственно в `D:\BothostBot`.
Приватный `.env` в этой папке содержит восстановленный старый токен и текущие настройки.
Не загружайте `.env` в Git и не публикуйте папку целиком без проверки.

1. Выберите Python, главный файл `main.py`, установку из `requirements.txt`.
   Если используете собственный Dockerfile, он уже добавлен.
2. В разделе переменных окружения Bothost перенесите значения из приватного `.env`.
   На хостинге обязательно замените `DATA_DIR` на `/app/data` и добавьте
   `DATABASE_PATH=/app/data/bot.sqlite3`.
3. Через приватный файловый менеджер Bothost перенесите СОДЕРЖИМОЕ локальной
   папки `data` в `/app/data`. Не передавайте эти файлы через публичный Git.
4. Только после загрузки данных запускайте бота на хостинге.
   Локальный бот при подготовке остановлен и заново не запускался.

## Данные и резервные копии

`bot.sqlite3` хранит офферы, их статусы, сообщения, профили и счётчик.
JSON-файлы хранят доступы, администраторов, подключения и статистику.
SQLite работает без отдельного сервера БД. Старые JSON скопированы без изменения содержимого.
Старые офферы, существовавшие только в памяти до подготовки, восстановить из JSON нельзя.

Папка `/app/data` предназначена Bothost для постоянных данных.
Перед обновлениями делайте приватную резервную копию всей папки, предварительно
остановив бота: для SQLite в режиме WAL важны также файлы `-wal` и `-shm`, если они есть.
Не запускайте несколько реплик: JSON и блокировка рассчитаны на один процесс/контейнер.
При собственном Dockerfile volume должен быть доступен на запись UID 1000.

## Границы защиты

`.gitignore` и `.dockerignore` исключают секреты, данные, логи и старые архивы.
Логи маскируют Telegram-токены. Приложение не раздаёт файлы через HTTP.
Это не защищает от владельца хостинга, доступа к панели/диску и компрометации аккаунта.
`.gitignore` не удаляет уже опубликованные секреты из истории Git.
Токен, который ранее попал в чат или публичный репозиторий, следует перевыпустить в BotFather;
в этой подготовке по запросу сохранён именно старый токен, его действительность не проверялась сетью.
